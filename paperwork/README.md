# 教師下載紙本對照組工作紙 PDF

參照 VL1 最新 v3 紙本安排，以本聊天提供 proposal 的 4.1、4.3.1、4.3.2 作對齊依據：兩組在正式授課前使用相同情境、概念、題目及提示；紙本用靜態圖及資料代替互動。每週工作紙與正式 10 題 SPSAI、4 題 CKT 前後測分開，不增加測驗題或學生意見題。

## 教師使用及派發

指定教師登入後按儀表板「下載紙本對照組工作紙 PDF」。毋須雲端密碼或先完成示範。材料語言初始跟隨介面，可獨立選繁中／英文，預覽或直接下載真正 PDF；不呼叫瀏覽器列印代替下載。

| 分冊 | 兩語各頁數 | 完整套裝頁碼 | 派發安排 |
| --- | --- | --- | --- |
| A：情境與原始探究設計 | 3 | 1–3 | 先派，保存原始觀察、假說、理由及設計，學生保留副本 |
| B：實驗資料、分析與結論 | 4 | 4–7 | 原始設計固定保存後才派 |
| C：學習重點及反思 | 2 | 8–9 | 原探究答案固定後才派，反思參閱 A 副本 |
| D：教師指引、參考答案及評分準則 | 8 | 10–17 | 只供教師 |
| 完整教師列印套裝 | 17 | 1–17 | 只供教師，分冊列印及派發 |

中英文各有 A、B、C、D、完整套裝五份檔案，共十份 PDF。學生 A–C 共 9 頁。姓名、班別及學號空白欄只出現在 A 首頁及 C 首頁，獨立分冊及完整套裝一致；不帶入任何學生或示範資料。

A3 合併前提、對照及裝置設計，繪圖框先於文字設計。B1 合併基本四裝置圖與四時間觀察表；B2 提供 10／20 min 結果，B3 提供 30 min 結果及自行計算欄，B4 合併圖表與現有結論。為使量尺可讀，VL2 不硬套 VL1 的兩頁 B。VL2 沒有延伸探究，不增加或恢復延伸題。C1 合併學習重點、同源科學圖、過程說明及證據界限；C2 保留反思。

所有文字作答及修訂欄為兩條橫線；數值讀數／計算使用空白表格，圖表及繪圖使用空白框。句子下拉選項轉成句內括號，圈選一項；變量及前提保留多選方格，內容及順序與目前 VL2 相同。兩項灰色提示與 VL 同步；英文採用使用者指定措辭。

資料圖來自同一恆定速度教學模型：0、10、20、30 min 四時間，A/B/C/D 原始讀數分別為 `[0,4,8,12]`、`[0,2.5,5,7.5]`、`[0,1.5,3,4.5]`、`[0,0.5,1,1.5]` cm。學生 B 只看量尺及結果圖，觀察表、計算及圖表答案留白；數字答案只印在 D。水面使用清楚線條，水跡加深，黑白仍可判讀。圖中液面對應尺子零點；浸入深度維持原有 2 cm，不加入未量度數值。

## 共用內容、版本及產生

`app.js` 的 `VL2InquiryContent()` 提供相同模型、條件、變量、前提、科學 SVG、參考文字及 Excel rubric；紙本來源不讀取學生 profile／state／欄位 value，不建立 freshState 或儲存事件。既有學生報告和紙本共用 REFERENCE_TEXT，沒有另手抄一份題目。

`source.js` 從目前題目 DOM 的 canonical 原文讀取題幹、提示、選項和學習重點，使用相同 i18n 引擎及已批准詞彙。`i18n-paper.js` 只新增材料介面與共用教師 rubric 的英文翻譯。紙本專用的派發說明在 `texts.js`，不增加學生評分題。

```sh
node paperwork/build.cjs
node paperwork/build.cjs --check
node tests/paperwork.cjs
python tests/paperwork_pdf.py
```

環境：Node 20+、Playwright 1.62.1、Chromium（預設 `/usr/bin/chromium`，或設 `CHROMIUM_PATH`）、Python 與 PyMuPDF 1.26.6。重建字型另需 FontTools 及 `fonts-noto-cjk`，執行 `python paperwork/subset-font.py`。PDF 嵌入 OFL 字型，保留可選取文字及向量科學圖，不是截圖 PDF。執行不需要 Google 密碼或正式收集端。

檔案格式：`VL2_A_zh_v1_<revision>.pdf` 等；下載名稱為 `VL2_紙本對照組_A_繁中_v1_<revision>.pdf`／`VL2_ControlGroup_A_EN_v1_<revision>.pdf`；完整套裝把 A 換成 `完整教師列印套裝`／`CompleteTeacherPack`。

revision 是共用內容與生成程式、版面及字型 fingerprint 的 SHA-256 前十位；更新來源後重新生成會自動使用新 revision。`manifest.json` 記錄內容版本、revision、來源 digest、頁數、完整套裝頁碼、檔名、檔案大小、checksum 及每頁作答規則。`source.json` 保存完整空白來源快照；`source-canonical.json` 保留可跨手機／作業系統比較的內容與圖形資料，忽略 SVG 字型量度造成的換行差異。

教師面板比對目前共用來源 digest，下載及預覽再核對 PDF 長度與 SHA-256；材料過期、毀損或不完整時拒絕提供。題目新增或刪除時生成器要求更新版面對應，避免默默缺題。改動題目、提示、翻譯、模型或版面後，重建並提交 generated 檔案。GitHub workflow 檢查版本及實際材料，重新生成審閱 artifact；不改 Pages 或 Apps Script 設定。

## 隔離及檢查

預覽與下載入口只在教師儀表板，函式也檢查教師模式；遵循 VL2 既有介面規則，並非額外 Google 身份驗證。靜態空白 PDF 是公開網站資產，不含個人資料。切換帳戶關閉材料預覽。操作沒有 save/log/計時/雲端/Excel 寫入，材料語言不改 VL 語言。

瀏覽器測試使用隔離本機配置，封鎖正式 Google 收集端；只在測試中暫停背景定期自動儲存／補傳，以確定唯讀操作的比較不受時間觸發影響。驗證十份實際下載與 checksum、預覽、教師入口、兩語、獨立語言、過期／毀損拒絕、手機下載，以及前後完整示範狀態、答案、圖片、計時、事件、本機／待傳資料和真正 Excel bytes 一致。

實際 PDF 測試逐頁驗證所有題幹／選項／提示／rubric、A4 分頁、嵌入字型、PDF 向量中的兩條作答橫線、姓名欄位置、頁邊界、批准詞彙及階段答案隔離。全部彩色頁、B/C 灰階頁輸出至 `/tmp/vl2-paper-review` 供視覺檢查。

## 研究者仍須確認

本 proposal 尚未提供正式 SPSAI／CKT 題本，本工作不建立或修改它們。活動 rubric 32 分不等於這兩個正式量表。跨 VL 的證據數量、難度、權重、人工評分一致性及靜態紙本的實作構念需要校準。proposal 提到自動資料視覺化，而目前 VL2 由學生自行標點，請核對研究描述與實際處理。每次活動時長未由 proposal 明定，兩組應使用研究者確認的相同可用時間。正式派發前仍需以實際印表機試印灰階 B/C。

# 西芹水分運輸：自學比較組工作紙（v2）

本模組是「西芹的紅色水跡：光照會改變水分運輸嗎？」。按使用者最新研究條件重製：實驗組使用 IBL＋VL；比較組沒有課前講授、不操作 VL，只靠工作紙自學。比較組採「概念解說 → 已解說示例 → 有提示練習 → 獨立應用 → 核對修正」，概念從開始即可閱讀。這項要求取代舊版紙本先探究、最後才揭示概念的安排，沒有改動學生 VL 的探究次序。

兩組各 **15–20 分鐘**。建議共同目標 18 分鐘：A 概念及示例 4 分鐘、B1–B2 有提示練習 3 分鐘、B3–B5 獨立應用 8 分鐘、C 核對修正 3 分鐘。這是安排目標，不是已驗證的學生實際用時，必須試教。

## 科學、方法及數據

A 提前使用 VL 的同源學習重點及葉片構造圖，解說葉肉表面水膜蒸發、氣室水汽經氣孔擴散、葉肉水勢下降、滲透補水、木質部水被抽出及蒸騰拉力；說明供水充足等合適條件下較強光照通常促進氣孔開啟與蒸騰。區分液態水分運輸與失水至大氣，西芹長柄是含木質部的葉柄，不是莖。

指定裝置不改：A 帶葉10 cm/1200 lux，B 帶葉20 cm/300 lux，C 帶葉30 cm/133 lux，D 不帶葉20 cm/300 lux。A/B/C 比較光強度，B/D 比較葉片有無。固定25°C、濕度及氣流、染液濃度、浸入2 cm、相近葉柄尺寸、A/B/C 相同葉面積；特別說明需監測溫度，燈距改變不能只假定沒有升溫。

目前模型在0/10/20/30 min 的 A/B/C/D 高度分別為 `[0,4,8,12]`、`[0,2.5,5,7.5]`、`[0,1.5,3,4.5]`、`[0,0.5,1,1.5]` cm；平均速度0.40/0.25/0.15/0.05 cm/min。B 只有尺圖與空表，不另標所有答案；答案只在 C 及教師完整套裝。A 的中性方法示例 P 是1.0→5.0 cm、20 min，平均0.20 cm/min；500 lux 的標點示例亦明確標記為方法示例，不混入正式模型數據。

速度用 `(30 min 高度 − 0 min 高度) ÷ 30`，兩位小數。X 光強度lux，Y 水跡平均上移速度cm/min；D 獨立，不能連入 A/B/C 趨勢。水跡速度不是直接蒸騰速率，B/D 不能單獨證明水汽只經氣孔散失，三光強度點不能推出未測範圍精確曲線。圖有清楚液面、加深水跡、固定尺零點及黑白可辨線條。

## 逐題配對、評分及研究使用

[繁中逐題配對](ALIGNMENT.zh.md)及[英文逐題配對](ALIGNMENT.en.md)由同一來源自動產生，也完整放在 D，列出「VL 原題／處理方式／新版題目／共同目標／理由」。保留合理計算與分析題；自由設計改為讀指定圖、補標示、解釋控制與公平比較；原始假說改為先教可測試性後評估「較好」這一未界定結果；反思改為數據解釋及錯誤修正。

D 的八個0/1/2回饋範疇分開記錄，不加成與 VL32分比較的活動總分。紙本讀尺不等同完整實驗操作；不把學習後評估假說當作原始預測表現，也不將操作量、完成率或時間換算 SPS 能力。成效使用另行兩組共同測驗；正式 SPSAI／CKT 題本尚未提供，本次不建立或改動。共同內容與合理技能練習保留，教學次序與互動差異是研究處理的一部分。

## 來源、版本及重建

學生 `app.js`、模型、帳戶、紀錄、學生 PDF、Excel、雲端及舊資料不改。`source.js` 只讀 canonical 題目 DOM 及 `VL2InquiryContent()` 的共用模型、條件、選項、學習點和 SVG；不讀學生 value/profile/state/storage。紙本等值題、教學示例、配對及回饋只在 `curriculum.js` 一個雙語來源；管理說明在 `texts.js`；`render.cjs` 排版。原 VL 提示及已批准英文詞彙支援保留，學生原文不會被材料功能翻譯或改寫。

內容版本 `VL2-paper-selfstudy-v2`，材料v2，來源 SHA-256 前十位 revision。檔案 `VL2_A_zh_v2_<revision>.pdf`，下載名稱 `VL2_西芹水分運輸_A_繁中_v2_<revision>.pdf`／`VL2_CeleryWaterTransport_A_EN_v2_<revision>.pdf`。`manifest.json` 自動記頁數、頁碼、時限、SHA-256及逐頁版面；前端無快取取得 manifest，核對來源摘要與 PDF bytes，不提供過期、損毀或未完成材料。修改來源、翻譯或排版後重建全部十份。

```sh
python paperwork/subset-font.py
node paperwork/build.cjs
node paperwork/build.cjs --check
node tests/paperwork.cjs
python tests/paperwork_pdf.py
node tests/language.cjs
```

環境：Node20+、Playwright1.62.1、Chromium（`CHROMIUM_PATH` 或 `/usr/bin/chromium`）、Python/PyMuPDF1.26.6；字型重建另需FontTools及Noto CJK。嵌入OFL字型，文字可選取、SVG與作答線為向量。GitHub workflow 檢查現有 fingerprint，重建供審閱；無需新增 Apps Script。

## 實際驗證與限制

測試在隔離瀏覽器封鎖正式 Google 收集端；手機為390×844觸控模擬，未宣稱實體手機／印表機或 Google 部署驗收。檢查全部十份實際PDF內容、科學標籤、嵌入字型、A4、兩條向量作答線、姓名欄、答案隔離、灰階圖；教師兩語下載／預覽、過期與損毀拒絕，以及前後答案、繪圖、計時、事件、本機／雲端待傳metadata和實際Excel bytes不變。PDF測試輸出全部彩色頁及A/B/C灰階頁到`/tmp/vl2-paper-review`供審閱。

研究者仍須試教15–20分鐘是否足夠、檢查實體灰階列印、正式共同測驗與評分者一致性；讀尺與完整操作的構念差異須寫入研究限制。最新使用者指定的自學研究條件及15–20分鐘安排優先於舊版工作紙安排。

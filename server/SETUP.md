# 啟用跨裝置中央紀錄（教師只需部署一次）

靜態 GitHub Pages 無法自行建立中央儲存。網站程式已備妥，但必須完成以下步驟才會真正同步。

1. 使用 **tzechingchan0605@gmail.com** 在 Google Drive 建立一份私人 Google 試算表，例如「VL2 中央學生紀錄」。不要公開試算表或紀錄資料夾。
2. 在該試算表選 **擴充功能 → Apps Script**，把本目錄 `Code.gs` 的完整內容貼入並儲存。
3. 執行 `setupCentralStore` 一次，完成 Google 授權。程式建立 Records 索引及私人 Drive 資料夾；完整答案、事件、原始假說及裝置圖保存在該資料夾，每次探究一個檔案。
4. 在 Apps Script **專案設定 → 指令碼屬性** 找到 `TEACHER_KEY`。私下保存它；它是讀取全班答案的教師憑證，不要寫進公開程式或分享给學生。若外洩，在此更換為新的長隨機值。
5. 選 **部署 → 新增部署 → 網頁應用程式**；執行身分選 **我**，誰可以存取選 **任何人**（包括未登入 Google 的訪客），然後部署。若學校限制公開網頁應用程式，需學校管理員允許或改用其他後端。
6. 複製以 `/exec` 結尾的網頁應用程式網址，填入專案根目錄 `cloud-config.js` 的 `url`，提交至 GitHub，等待 Pages 更新。此網址可公開；教師金鑰不可公開。更新 Apps Script 程式時，須編輯部署並選取新版本。
7. 學生重新整理網站並登入，答案自動上傳；頁底顯示「✓ 答案已同步至教師中央紀錄」才代表收到中央確認。斷線時保留本機待傳資料，重連自動重試；清除瀏覽器資料會刪除尚未送出的資料。離開時不能保證瀏覽器完成網路請求，所以請等同步確認。
8. 教師在任何裝置用指定電郵進入儀表板，輸入 `TEACHER_KEY` 並按「連線／重新整理中央學生紀錄」。下載 Excel 時重新讀取中央資料，維持原有六個工作表、顏色及評分公式。這是由中央紀錄產生的最新 Excel；已下載並人工評分的 Excel 不會自動更新或回傳教師分數。

## 上線驗收

- 手機與電腦分別登入不同學生並輸入不同答案，等兩邊同步成功。
- 在第三個瀏覽器登入教師、連線，確認可看兩份完整紀錄，匯出的 Excel 包含兩人。
- 同一學生再登入一次：應增加新的探究，不覆蓋舊次。
- 教師做完整示範及匯出 PDF，中央紀錄數量應不增加。
- 金鑰錯誤時不可讀取紀錄；斷線後恢復連線，待傳答案應成功補送。

舊版紀錄只能由原本保存答案的瀏覽器補送：更新網站後在該瀏覽器登入，程式會把當地學生紀錄補送至中央。沒有中央同步前，另一個裝置無法取回手機內的歷史資料。

每次探究有獨立 UUID 及私有寫入憑證，同一次保存更新原紀錄；重複登入保留所有次數。教師示範在前端及後端均排除。教師憑證保留於目前頁面記憶體，重新載入需重輸入；學生無法透過 list 端點讀取全班資料。學生姓名／電郵是自行填寫，並非 Google 身分驗證。公開提交端點供課堂使用，仍受 Apps Script 執行及 Drive 配額限制；若需大規模或強制學生身份驗證，应另用學校後端。

本機測試 `node tests/cloud.cjs` 執行真實 `Code.gs` 邏輯及獨立瀏覽器流程，Google 服務以測試替身提供。它不能代替部署後的跨裝置、Google 授權及 CORS 驗收。
